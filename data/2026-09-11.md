研究动机: 由于HBM接口对本质上可并行的模型施加了残酷的顺序执行约束，导致大规模概率能量模型被认为不可扩展，但实际上问题在于GPU架构本身对于这一类AI模型并非可扩展的处理器架构。

主要方法: 使用概率模拟片上内存计算（AIMC）处理器的详细事务级模型（TLM）进行建模和分析，通过消除HBM接口并在片上内存内直接执行计算来优化模型执行。

实验 / 验证: 利用详细的事务级模型（TLM）对概率模拟片上内存计算（AIMC）处理器进行建模，与数据中心级硬件进行性能对比评估。

主要结果: 通过消除HBM接口并在片上内存内直接执行计算，相同的能量模型可以比数据中心级硬件快1000倍以上执行。

结论: GPU架构本身——由于其对HBM接口的依赖——并非大规模概率能量模型的可扩展处理器架构，通过采用片上内存直接计算方法可显著提升模型性能。

中文摘要: 本报告扩展了我们之前的工作（第一部分），该工作引入了一种基于能量的模型，用于在不确定性下进行学习和决策。该模型利用随机朗之万动力学持续演化神经元状态和模型权重的近似概率分布。然而，正如第一部分所指出并通过基于GPU的实现所确认的那样，这种性质的大规模概率能量模型由于过高的执行延迟而面临显著的扩展性挑战。这种延迟源于根本的不匹配：低算术强度的超大规模并行模型（如能量模型）在依赖高带宽内存接口的处理器架构（如GPU）上执行。HBM对本质上可并行的模型施加了残酷的顺序执行约束，造成此类模型不可扩展的假象。实际上，正是GPU架构本身——由于其对HBM接口的依赖——对于这一类AI模型来说并非可扩展的处理器架构。在本报告中，我们利用概率模拟片上内存计算（AIMC）处理器的详细事务级模型（TLM）证明，通过消除HBM接口并在片上内存内直接执行计算，相同的能量模型可以比数据中心级硬件快1000倍以上执行。

英文原始摘要: This report extends our previous work (Part 1), which introduced an energy-based model for learning and decision-making under uncertainty. The model leverages stochastic Langevin dynamics to continuously evolve approximate probability distributions over neuron states and model weights. However, as noted in Part 1 and confirmed through GPU-based implementations, large-scale probabilistic energy-based models of this nature face significant scalability challenges due to excessive execution latency. This latency stems from a fundamental mismatch: massively parallel models with low arithmetic intensity (such as energy-based models) are being executed on processor architectures like GPUs that rely on high-bandwidth memory (HBM) interfaces. The HBM imposes brutally sequential execution constraints on inherently parallelizable models, creating the false impression that such models are unscalable. In reality, it is the GPU architecture itself, with its dependence on HBM interfaces, that is not a scalable processor architecture for this class of AI model. In this report, we demonstrate using a detailed transaction-level model (TLM) of a probabilistic analogue in-memory computing (AIMC) processor that the same energy-based model can execute well over 1000x faster than data-center-grade hardware by eliminating the HBM interface and performing computation directly within on-chip memory.
